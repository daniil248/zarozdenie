# Авторизация и доступ

## Вход (логин)

**Эндпоинт:** `POST /api/user/login`

**Тело запроса (JSON):**

| Поле | Описание |
|------|----------|
| `number` | Номер телефона (как в БД, строка) |
| `password` | Пароль |

Ответ выдаёт access/refresh токены (cookies на фронте: `accessToken`, `refreshToken`).

**Готового «логина/пароля по умолчанию» в коде нет** — пользователи создаются через регистрацию или вручную в БД.

---

## Регистрация

`POST /api/user/registration` — создаёт пользователя с ролью по умолчанию `USER`.

---

## Раздел «Анкеты» (`/profiles`)

В `middleware` для страницы анкет задано `status: true`: нужны **и** токены, **и** `user.status === true` в БД (аккаунт «одобрен» модерацией).

Список анкет приходит с API (`GET /api/product/...`). **Полнота списка = данные в PostgreSQL**, не файлы в репозитории.

---

## Админка (`/admin`, `/admin/orders`, …)

В `definePageMeta({ admin: true })`: нужен пользователь с **`role: ADMIN`** в БД + валидные токены.

Создать админа можно только на бэкенде/в БД (Prisma: таблица `User`, поле `role`).

---

## CORS (GitHub Pages)

Если фронт открыт с `https://daniil248.github.io`, на API в `.env`:

```env
CORS_ORIGIN=https://daniil248.github.io
```

Или временно `CORS_ORIGIN=true` только для отладки (не для продакшена).
